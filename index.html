The pairs that get confused

A theory paper is mostly a vocabulary test, and the words that cost marks are the ones that look alike but mean different things. Read these before working through W1–W5.

Cardinality (W3 vs W4)
class 3: the number of rows in a relation. class 4: the max half of a multiplicity — at most how many. Same word, unrelated meanings.
Degree (W3 vs W4)
class 3: the number of columns a relation has. class 4: the number of entities taking part in a relationship (2 = binary, 3 = ternary).
Data vs Database Administrator
Two different roles despite the names. The Data Administrator plans and defines the system at the start (Plan, Define); the Database Administrator configures and maintains it at the end (Config, Maintain/Tune).
Superkey / Candidate / Primary
Superkey identifies a row and may carry surplus attributes. Candidate is a superkey that cannot be reduced further. Primary is the candidate that was chosen; the rest become alternate keys.
min .. max
The first number (min) is participation — is it compulsory? (0 = optional, 1 = mandatory). The second (max) is cardinality — if it exists, how many at most?
Composite vs Multi-valued
Composite = one value made of several components (address = street + city + postcode). Multi-valued = several values at the same moment (three phone numbers). Different axes entirely.
Strong vs Weak entity
Strong = has a primary key of its own and borrows from nobody. Weak = cannot identify itself from its own attributes, so it borrows the strong entity's PK into a composite key through an identifying relationship.
Entity vs Referential integrity
Entity integrity: every relation must have a primary key and it may never be null. Referential integrity: a foreign key's value must match an existing primary key, or be wholly null.
ER vs Instance Diagram
ER Diagram = the schema — boxes, lines, attributes, at design time. Instance Diagram = the actual stored data and the links between values, once the system is running.
Bottom-up vs Top-down
Bottom-up starts at the attributes (a receipt in your hand, picked apart). Top-down starts at the entities (the big picture, refined downward). The ER model is top-down.
ANSI-SPARC
The three-level architecture — External / Conceptual / Internal — proposed in 1975. It never became a formal standard, yet it is still the basis for understanding how a DBMS works.
Derived attribute
An attribute computable from others, not necessarily in the same entity type. Written with a leading slash: /totalAmount.
W1

Introduction to Database

6 Aug 2026 What a database is, how it differs from a pile of files, and who does what around it.

SQL, in four groups

DDLData Definition — CREATE, ALTER, DROP
DMLData Manipulation — SELECT, INSERT, UPDATE, DELETE
DCLData Control — GRANT, REVOKE
TransactionCOMMIT, ROLLBACK, SAVEPOINT, SET ISOLATION
  • Originally SEQUEL (Structured English Query Language), by Donald Chamberlin and Raymond Boyce at IBM in the 1970s; renamed SQL before commercial release in 1979.
  • Standardised by ANSI in 1986 and by ISO in 1987.

What makes it a database system

  • Self-describing — the DBMS catalog stores the structure, data types and constraints. That is the meta-data.
  • Program-data independence — the structure or storage format can change without rewriting the programs.
  • Data abstraction — the data model hides the real storage details.
  • Multiple views — each group of users sees only the slice it cares about.
  • Multi-user — concurrency control keeps it correct when many work at once, and the recovery subsystem guarantees a finished transaction is recorded permanently.

Watch out

  • Data Administrator ≠ Database Administrator. Nearly the same name, different jobs: the first plans and defines at the start, the second configures and maintains at the end.
  • The three requirements come as a set: Data Persistency (data outlives the program that made it), System Reliability (correct and fast recovery), Scalability.
  • The main sequence in the Actors diagram: System Planning → System Definition → Requirement Collection → Database Design → System Implementation → System Maintenance.

Database Environment & Architecture

13 Aug 2026 The three levels that separate what a user sees from what is actually stored — and why that separation is worth having.

Database design, three stages

1 Conceptualindependent of any DBMS → an ER Diagram
2 Logicaldepends on implementation → tables and constraints
3 Physicalhow it is stored for efficient access → files, indexes, partitions
  • It all starts from Requirement Collection and Analysis, before stage 1.
  • The slide's analogy: a 2D floor plan is the conceptual/logical model; a 3D model with real materials and colours is the physical one.

Multi-user architectures

Teleprocessingone powerful central machine with many "dumb" terminals; the load all falls centrally
File-Serverthe server does nothing but serve files; a full DBMS on every workstation and a great deal of data crossing the network
Two-Tierclient presents and runs the logic (a fat client); server serves data
Three-Tierthin client · application server holds the business logic · database server holds the data

Watch out

  • Five kinds of data model, in the slide's order: Hierarchical (a tree, one parent) → Network (a many-to-many graph) → Relational (plain tables) → Object-oriented → Object-relational.
  • A data model is defined in three parts: a structural part, a manipulative part, and an integrity constraint part.
  • ODBC is Microsoft's; JDBC is Java's. Both are database-oriented middleware.
  • Three-tier's advantages, often asked: cheaper hardware, one place to maintain the logic, modularity, and easier load balancing.

The Relational Model

20 Aug 2026 The heaviest vocabulary of the five weeks, and the richest ground for a theory paper. The lecturer opened it herself: "today we will also come to understand the relational model through its vocabulary." Formal ↔ informal terms

RelationTable
AttributeColumn / Field
TupleRow / Record
Domainall possible column values
Schema of a RelationTable Definition — R(A1, A2, …, An)
Cardinalitythe number of rows — changes with the instance
Degreethe number of columns — fixed by the schema

Properties of a relation

  • Its name is distinct from every other relation.
  • Every cell holds exactly one atomic value — it cannot be broken down further.
  • All values of one attribute come from the same domain.
  • No duplicate tuples.
  • Row order does not matter, but column order does — a tuple is an ordered list of values.
  • null is the special value meaning unknown, not available, or inapplicable to that tuple.

Watch out

  • The slides look self-contradictory — slide 6 says attribute order is irrelevant, property 7 says it matters. They do not actually conflict. In set theory a relation is a set of attributes, so order is meaningless; in practice an INSERT naming no columns must list values in the declared order or the data lands in the wrong columns.
  • A slide typo: STUDENTS says "four attributes" then lists five. Five is correct (degree = 5).
  • In the terminology figure, cardinality = 4 and degree = 5 are measured on PrivateOwner, not PropertyForRent (which has 6 rows and 8 columns). An exam question will use that.

The facts most easily turned into an exam question

This paper is theory only — no practical half. What that can test is definitions, confusable pairs, tables with a clear ordering, and reading a diagram. Everything below comes from the slides or from what was said in class.

Integrity constraints, four groups — class 3

The purpose of all of them: to prevent accidental damage to the data.

Keythe set of attributes that identifies each tuple uniquely
Entity integrityevery relation must have a primary key, and a primary key may never be null
Referential
integrity		an FK's value must match a primary key that actually exists in the referenced relation, or be wholly null
GeneralUnique, Check, Not Null — extra rules set by a user or the DBA for a business condition, such as Check (salary > 15000)
"Or be null" applies only when that FK column is not declared NOT NULL — and if you intend to use ON DELETE SET NULL, that column must never be NOT NULL.

Referential actions — class 3

What happens when an UPDATE or DELETE touches a parent key that child rows still reference.

RESTRICTrefuses the delete or update. Naming RESTRICT is the same as writing nothing — it is the default (NO ACTION likewise)
CASCADEdeletes or updates the parent, then does the same to the matching child rows
SET NULLdeletes or updates the parent, then sets the child rows' FK column to NULL
The trap: a referential action does nothing for INSERT. ON DELETE/ON UPDATE govern only what happens to child rows when a parent is deleted or updated. Inserting a child row pointing at a key that does not exist is refused regardless of which action is set.

Which operation can violate what — class 3

An asymmetric table with a clear pattern — ideal multiple-choice material.

INSERTcan violate every kind — domain, key, referential integrity, entity integrity
DELETEcan violate referential integrity and nothing else — when the PK of the row being deleted is still referenced
UPDATEviolates the domain and NOT NULL of the attribute changed, and possibly more depending which — especially changing a PK (children lose their parent) or an FK (it may point at nothing)
For DELETE, one of three must be chosen at design time, for every foreign key: RESTRICT refuses, CASCADE deletes on through, SET NULL sets the referencing FK to null.

Where the relational model came from — class 3

Names, a year and a prize — the easiest multiple-choice item there is to write.

Multiplicity notation — class 4

All six come straight off the slide. * and n are interchangeable — both mean many.

The ones people get wrong
Mixing up the two cardinalities Class 3's cardinality is the number of rows; class 4's is the max half of a multiplicity. Degree does the same thing: class 3 means columns, class 4 means how many entities take part. Both weeks sit on the same paper.
Reading the number on the wrong side She said outright this is the mistake students make most. Reading from A to B, look at the number on B's side, not A's, and open the sentence with "one A …".
Putting foreign keys on a conceptual diagram This stage carries primary keys only — no FKs, no unique, no check, no not null, because implementation has not been reached. It asks only what the main data is, how it relates, and what the primary key is.
Expecting a referential action to help an INSERT ON DELETE/ON UPDATE govern only what happens to child rows when a parent is deleted or updated. Inserting a child pointing at a key that does not exist is refused whatever you set.
Thinking a changed value is multi-valued Multiple-valued means several values held at the same moment — three phone numbers. Changing your surname is not: at any one time you have exactly one.
Using min to name a 1:1 or 1:* To call something one-to-one / one-to-many / many-to-many, look at the max on both sides only. 0..1 ↔ 0..* is still one-to-many even though both mins are zero.
Data Administrator vs Database Administrator The names are close enough to make an excellent distractor. The Data Administrator does Plan and Define at the start; the Database Administrator does Config and Maintain/Tune at the end.
Leaving a relationship line unnamed The name on the line is always required; the ▶ marking reading direction is not — she allows it either way. Stuck for a name? Lift the verb straight out of the requirement sentence.
Open questions — answer in your own words
A relation has 6 rows and 8 columns. What are its cardinality and degree?
cardinality = 6 · degree = 8Cardinality counts rows and changes with the instance — delete one and it becomes 5. Degree counts columns and is fixed by the schema; only an ALTER TABLE changes it. Note that in class 4 both words mean something else entirely.
Is {StudentNo, Email} a candidate key of Students?
No — it is only a superkey, because it can be reduced.A candidate key needs both uniqueness and irreducibility. This set does identify a row, but drop either attribute and it still does — so it is reducible and fails the second test. StudentNo alone and Email alone are the candidate keys.
A foreign key with no ON DELETE clause at all — what happens when you delete a parent that still has children?
The delete is refused — the default is RESTRICT.Writing RESTRICT is identical to writing nothing (NO ACTION likewise). To make it cascade you must DROP the old constraint and ADD it back with ON DELETE CASCADE. MySQL Workbench shows this plainly: the Related Tables panel reads On Update: RESTRICT / On Delete: RESTRICT.
Which integrity constraints can a DELETE violate?
Exactly one — referential integrity.A DELETE puts no new value in, so it cannot violate a domain, a key, or entity integrity. The only way it can go wrong is when the PK of the row being removed is still referenced elsewhere. Compare INSERT, which can violate every kind.
Given Staff 1..1 — Manages ▶ — 0..1 Branch, how do you read it from Branch to Staff?
"One branch must have a manager, and exactly one."Reading Branch → Staff means looking at the number on Staff's side, which is 1..1. min=1 makes it mandatory participation; max=1 means at most one. Look at Branch's 0..1 by mistake and the whole sentence comes out wrong — the trap she warned about.
Should dateAdvert and cost live on Newspaper or on PropertyForRent?
Neither — they are attributes of the relationship.Not on PropertyForRent: one property can be advertised in several papers, on different days, at different prices. Not on Newspaper: one paper carries many listings at differing costs. This data can only exist once the relationship itself occurs — so it hangs off the line by a dashed line into a box whose header is left blank.
In a dormitory business with four identically laid-out buildings, what kind of entity is Rooms(roomNo, roomCapacity)?
A weak entity — roomNo alone cannot identify a room.All four buildings number their rooms the same way, so 101 names four real rooms. Two fixes: (1) borrow bldgNo from Buildings through an identifying relationship to form a composite key, making 101+A distinct from 101+B; or (2) invent a surrogate key such as a running roomID — which she said is not wrong.
Is ANSI-SPARC a formal standard?
No. Proposed in 1975, it never became one.The slide says so in as many words, yet it is still used as the basis for understanding how a DBMS works. ANSI = American National Standards Institute; SPARC = Standards Planning And Requirements Committee. What it buys is data independence — an upper schema is unaffected when a lower one changes.
Which part of the ANSI-SPARC picture belongs to the OS rather than the DBMS?
The physical storage on disk, below the internal level.The slide puts a "DBMS" label beside Conceptual and Internal, and an "OS" label beside Database. The DBMS owns the external, conceptual and internal levels; only the real files on disk are the operating system's job. The internal level is still the DBMS's — that is the part people get wrong.
Is the ER model bottom-up or top-down?
Top-down.It begins by identifying the important data (entities) and the relationships between them, and only then adds attributes and constraints. Bottom-up starts at the attribute level and groups upward, which suits small databases. Her analogy: bottom-up is being handed a receipt and picking it apart. In real work you can mix the two — no rule forbids it.
What is the degree of Registers between Staff, Branch and Client, and what is it called?
Degree 3 — a ternary relationship.A relationship's degree is how many entities take part: 2 = binary (the most common), 3 = ternary, 4 = quaternary, looping back to itself = recursive. Registers must be ternary because one registration has to record all three things — which client, with which member of staff, at which branch.
What does a recursive relationship have to do with the SQL you already know?
It is where SELF JOIN comes from.A table can join to itself precisely because its own rows relate to one another. The slide's example is Supervises, where Staff points back at Staff with the role names Supervisor and Supervisee. Week 3 showed the same shape already: EMPLOYEE.Super_ssn is an FK pointing back at EMPLOYEE.Ssn.
Why is storing an address as one single attribute not automatically wrong?
Because it depends on what the data is for.She gave an example not on the slides. If you will analyse it later — which province do most customers come from? — split it, because GROUP BY and ORDER BY then work easily. If it is backup data outside the core mission, such as an emergency contact's address in a hospital system, one attribute is fine. Her summary: "there is no design that is 100% correct; it depends on the reasoning behind it" — you must be able to justify your choice.

Which group do GRANT and REVOKE belong to?
  1. DDL
  2. DML
  3. DCL
  4. Transaction Control

DCL = Data Control Language, which governs privileges. DDL defines structure (CREATE/ALTER/DROP); DML manipulates data (SELECT/INSERT/UPDATE/DELETE); Transaction Control is COMMIT/ROLLBACK/SAVEPOINT.

Which is not one of the three requirements a database system must satisfy?

  2. System Reliability
  3. Scalability
  4. Portability
tap for the answer

The slide gives exactly three: Persistency (data outlives the program that made it), Reliability (correct and fast recovery after a crash), Scalability (large volumes and many concurrent users). Portability is not on the list.

Which role does Plan and Define at the start of the project?
  1. Data Administrator
  2. Database Administrator
  3. Database Designer/Analyst
  4. Application Developer
tap for the answer

The first two names are close enough to make an excellent distractor. The Data Administrator does Plan → System Planning and Define → System Definition, at the start. The Database Administrator does Config → System Implementation and Maintain/Tune → System Maintenance, at the end.

Which statement about the ANSI-SPARC architecture is correct?
  1. It became an ISO standard in 1975
  2. It was proposed in 1975 but never became a formal standard
  3. It became an ANSI standard in 1986
  4. It has four levels
tap for the answer

The slide says outright that it never became a formal standard, yet it is still the basis for understanding how a DBMS works. 1986/1987 are the years ANSI and ISO standardised SQL — a different thing entirely. And there are three levels, not four.

In the ANSI-SPARC picture, which part is the operating system's job rather than the DBMS's?
  1. The external level
  2. The conceptual level
  3. The internal level
  4. The real files on disk, below the internal level
tap for the answer

The slide puts a DBMS label beside Conceptual and Internal, and an OS label beside Database. The DBMS owns external, conceptual and internal; the OS owns the actual storage. The strongest distractor is the internal level, because it sounds like hardware — but it is still the DBMS's: the internal schema is the description of how it is stored, not the files themselves.

What is the output of conceptual database design?
  1. An Entity Relationship Diagram
  2. Tables and constraints
  3. Data files and indexes
  4. A requirement specification
tap for the answer

The three stages line up cleanly: Conceptual → ER diagram (no DBMS chosen yet) · Logical → tables and constraints · Physical → data files, indexes, partitions, block sizes. A requirement specification is the output of System Definition, which comes before all three.

Which architecture has a "fat" client?
  1. Teleprocessing
  2. File-Server
  3. Two-tier client-server
  4. Three-tier client-server
tap for the answer

In two-tier the client handles both presentation and the business logic, so it consumes more resources — the slide calls it fat and lists it as a drawback. Three-tier moves the logic to an application server, making the client thin. Teleprocessing uses "dumb" terminals that cannot compute at all, so neither word applies.

Whose standard is ODBC?
  1. Microsoft
  2. Oracle
  3. IBM
  4. Java (Sun/Oracle)
tap for the answer

ODBC (Open Database Connectivity) is Microsoft's — one interface reaching many kinds of database through drivers. JDBC is the Java set of methods doing the same job. Both are database-oriented middleware.

Who proposed the relational model, and when?
  1. Donald Chamberlin, 1974
  2. E. F. Codd, 1970
  3. Peter Chen, 1976
  4. E. F. Codd, 1979
tap for the answer

Dr. E. F. Codd of IBM Research, in A Relational Model for Large Shared Data Banks, Communications of the ACM, June 1970 — the work that won him the ACM Turing Award. Chamberlin did SEQUEL/SQL, a different thing; 1979 is SQL's commercial release.

A relation holds 6 tuples and 8 attributes. What is its degree?
  1. 6
  2. 8
  3. 48
  4. It depends on the current instance
tap for the answer

Degree = the number of attributes (columns) = 8, fixed by the schema. Cardinality = the number of tuples (rows) = 6, and that does change with the instance — which is what the last option describes. Note that both words mean something else entirely in class 4.

Which is not a property of a relation?
  1. Each cell holds exactly one atomic value
  2. There are no duplicate tuples
  3. The order of the tuples matters
  4. All values of one attribute come from the same domain
tap for the answer

Row order does not matter — a relation is a set of tuples, and reordering them leaves the same relation. What does matter is column order, because a tuple is defined as an ordered list of values, so an INSERT naming no columns must follow the declared order. This is the point where the slides look self-contradictory but are speaking from two angles.

A superkey none of whose proper subsets is itself a superkey is called a…
  1. Primary key
  2. Candidate key
  3. Alternate key
  4. Composite key
tap for the answer

That is the irreducibility property, which together with uniqueness defines a candidate key. A primary key is the candidate that was chosen; an alternate key is one that was not. A composite key describes a key built from several attributes — a different axis of classification altogether.

What does the entity integrity constraint state?
  1. An FK's value must match an existing PK, or be null
  2. Every relation must have a primary key, and it may never be null
  3. Every cell must hold an atomic value
  4. A value must lie within its attribute's domain
tap for the answer

The first option is referential integrity — the strongest distractor, because the two are routinely swapped. The third is a property of a relation, not an integrity constraint. The fourth is a domain constraint.

A foreign key with no ON DELETE clause behaves the same as which action?
  1. RESTRICT
  2. CASCADE
  3. SET NULL
  4. SET DEFAULT
tap for the answer

RESTRICT is the default, so writing it and writing nothing are identical (NO ACTION likewise). To make it cascade you must DROP the constraint and ADD it back with ON DELETE CASCADE. MySQL Workbench shows this plainly — the Related Tables panel reads On Update: RESTRICT / On Delete: RESTRICT.

Which integrity constraint can a DELETE violate?
  1. Domain constraint
  2. Entity integrity
  3. Referential integrity
  4. All of them
tap for the answer

A DELETE puts no new value in, so it cannot violate a domain, a key, or entity integrity. The only way it can go wrong is when the PK of the removed row is still referenced. The last option is the answer for INSERT, which can violate every kind.

A Registers relationship joining Staff, Branch and Client has what degree?
  1. 2 — binary
  2. 3 — ternary
  3. 4 — quaternary
  4. It depends on how many attributes it has
tap for the answer

A relationship's degree is how many entities take part — three here, so ternary. One registration must record all three things: which client, with which member of staff, at which branch. The last option is a distractor trading on class 3's degree of a relation, which counts columns.

In the multiplicity 0..*, what does the 0 tell you?
  1. Participation — taking part is optional
  2. Cardinality — at most zero occurrences
  3. That the relationship is one-to-many
  4. That the attribute may be null
tap for the answer

min..max, always. min = participation — is it compulsory? (0 = optional, 1 = mandatory). max = cardinality — if it exists, how many at most? The second option swaps the two. The third is wrong because naming 1:1 / 1:* / *:* uses the max on both sides, not this one number.

In the UML notation, what does telNo [1..3] mean?
  1. A composite attribute with three components
  2. A multi-valued attribute holding between 1 and 3 values
  3. A derived attribute computed from three others
  4. The multiplicity of a relationship
tap for the answer

Square brackets after an attribute name are the notation for a multi-valued attribute, read as "at least 1 number, and at most 3 stored". Composite uses indentation under a parent attribute; derived uses a leading /; and a multiplicity is written on the line between boxes, not after an attribute name.

On a conceptual-level ER diagram, what do you show?
  1. Primary keys only
  2. Primary keys and foreign keys
  3. Primary keys, foreign keys and NOT NULL
  4. All keys and every constraint
tap for the answer

She flagged this as the single most important rule of this stage. The conceptual level has not reached implementation, so it asks only three things: what the main data is, how it relates, and which attribute is the primary key. Foreign keys and unique/check/not null belong to the logical stage — week 8's material.
